> **版本**: v1.0
> **日期**: 2026-08-02
> **参与者**: User（用户）、Host（主机/电脑端软件）、MCU（主控固件）、SE（安全芯片）、Network（区块链网络）

## 1. 首次初始化（设备重置 / 生成新钱包）

```
User          Host           MCU            SE
 │              │              │              │
 │ 1 ResetDevice│              │              │
 │─────────────>│ 2 转发       │              │
 │              │─────────────>│ 3 rng_self_test()
 │              │              │─────────────>│
 │              │              │ 4 健康       │
 │              │              │<─────────────│
 │              │              │ (失败→显示错误,停机)
 │              │              │              │
 │              │              │ 5 int_entropy=TRNG(32B)
 │              │              │─────────────>│
 │              │              │ 6 SE_TRNG(32B)
 │              │              │<─────────────│
 │ 7 显示内部熵(hex)供校验     │              │
 │<─────────────│              │              │
 │ 8 确认       │              │              │
 │─────────────>│ 9 EntropyRequest           │
 │              │<─────────────│              │
 │              │ 10 ext_entropy(主机熵)      │
 │              │─────────────>│ 11 HKDF-Extract
 │              │              │    salt+int||ext → PRK
 │              │              │ 12 HKDF-Expand → seed
 │              │              │─────────────>│ 13 存入SE
 │              │              │              │    (永不可读出)
 │ 14 逐词显示助记词(仅一次)   │              │
 │<─────────────│              │              │
 │ 15 手抄确认(乱序抽查3词)    │              │
 │─────────────>│ 16 校验通过  │              │
 │              │ 17 完成      │              │
 │<─────────────│              │              │
```

**关键安全点**:
- 步骤 3 失败直接停机，不生成任何密钥
- 步骤 11-12 使用 HKDF（非裸 SHA256），核心熵（SE1/SE2/主控/host）+ 物理熵池混合（2026-08-11 起，见 08_多熵源设计）
- 步骤 14 显示期间 Host 无数据通道

## 2. 交易签名（Clear Sign 主流程）

```
User          Host           MCU            SE            Network
 │              │              │              │              │
 │ 1 构造交易   │              │              │              │
 │─────────────>│ 2 PSBT/rawTx │              │              │
 │              │─────────────>│ 3 解析交易    │              │
 │              │              │ 4 parsed_intent             │
 │              │              │   (to/amount/fee/method)    │
 │ 5 屏幕逐字段显示            │              │              │
 │<─────────────│              │              │              │
 │              │              │ risk=unknown? │              │
 │              │              │  →红色警告+长按确认          │
 │ 6 人工确认(按钮/触摸)       │              │              │
 │─────────────>│              │ 7 请求签名    │              │
 │              │              │─────────────>│ 8 PIN验证     │
 │ 9 输入PIN(乱序键盘)         │              │              │
 │────────────────────────────>│              │              │
 │              │              │              │ 10 RFC6979   │
 │              │              │              │    确定性nonce│
 │              │              │              │ 11 SE内签名   │
 │              │              │ 12 signature │              │
 │              │              │<─────────────│              │
 │              │ 13 签名结果   │              │              │
 │              │<─────────────│              │              │
 │              │ 14 广播      │              │              │
 │              │─────────────────────────────────────────>│
 │              │ 15 anti-exfil证明(可选验证) │              │
```

**关键安全点**:
- 步骤 5：屏幕显示与签名数据必须同源（防"显示A签B"）
- 步骤 8：PIN 验证在 SE 内比对，MCU 不知 PIN 明文
- 步骤 11：私钥不出 SE，只输出签名

## 3. PIN 错误与指数退避（无自毁）

```
User          MCU            SE
 │              │              │
 │ 1 输入PIN    │              │
 │─────────────>│ 2 verify     │
 │              │─────────────>│ 3 比对pin_hash
 │              │              │ 4 失败:
 │              │              │   fail_count++
 │              │              │   lock_until=now+2^n秒
 │              │              │   (n=fail_count, 封顶24h)
 │              │              │   持久化到SE
 │              │ 5 显示"请等待X"              │
 │<─────────────│              │
 │ 6 断电重启   │              │
 │─────────────>│ 7 读lock_until              │
 │              │<─────────────│ 8 继续倒计时(不清零)
 │ 9 倒计时结束,重新输入        │              │
 │─────────────>│ 10 成功→fail_count=0        │
```

**红线**: 任何路径都无擦除分支。胁迫 PIN 仅切换 SeedVault 视图（诱饵），真种子保持完整。

## 5. 自动签名（限额策略）

```
User          Host           MCU            SE
 │              │              │              │
 │ 1 设置策略(单笔/窗口限额)   │              │
 │─────────────>│ 2 请求修改   │              │
 │              │─────────────>│ 3 PIN验证     │
 │              │              │─────────────>│ 4 pending_change=true
 │              │ 5 "24小时后生效"            │
 │<─────────────│              │              │
 │   ...(24h冷静期)...         │              │
 │              │              │              │ 6 策略激活
 │ 7 策略内交易 │              │              │
 │─────────────>│ 8 转发       │              │
 │              │─────────────>│ 9 请求签名    │
 │              │              │─────────────>│ 10 检查:
 │              │              │              │   amount ≤ per_tx_limit?
 │              │              │              │   window_spent+amount ≤ window_limit?
 │              │              │              │ 11 是→直接签名
 │              │              │              │    window_spent+=amount(持久化)
 │              │              │              │ 12 否→回落手动Clear Sign
 │              │ 13 签名结果   │              │
 │              │<─────────────│              │
```

**关键安全点**: 策略状态（window_spent/window_start）持久化在 SE，断电不能重置额度；策略修改有 24h 冷静期防瞬时劫持。

## 6. 多签协同（M-of-N）

```
User-A        Device-A       Coordinator    Device-B ... Device-N     Network
 │ 1 同一PSBT  │              │              │                          │
 │────────────>│ 2 解析       │              │                          │
 │ 3 Clear Sign确认           │              │                          │
 │────────────>│ 4 部分签名    │              │                          │
 │             │ 5 sig_A      │              │                          │
 │             │─────────────>│ 6 收集        │                          │
 │                            │ 7 转发        │                          │
 │                            │─────────────>│ 8 各自独立Clear Sign     │
 │                            │              │   (同一交易意图)          │
 │                            │ 9 sig_B...    │                          │
 │                            │<─────────────│                          │
 │                            │ 10 集齐M个→合成完整交易                   │
 │                            │───────────────────────────────────────>│
```

**关键安全点**: 每个签署人必须在自己的设备上独立看到并确认同一 parsed_intent，杜绝"协调器给A看X、给B看Y"。
