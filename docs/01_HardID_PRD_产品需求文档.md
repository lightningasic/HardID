# HardID 硬件钱包 — 产品需求文档 (PRD)

> **版本**: v1.0
> **日期**: 2026-08-02
> **产品**: HardID Hardware Wallet
> **定位**: 极致精简、完全开源、以签名安全为唯一核心的硬件钱包
> **上游**: 自 2014 年 BitExchange Wallet（TREZOR fork）演进而来

---

## 1. 产品概述

### 1.1 背景与愿景
HardID 从 BitExchange Wallet 进化而来，坚持三条原始原则：**完全开源、极致精简硬件、私钥全生命周期不出设备**。在 milk sad（熵不足盗币）与 wallet.fail（STM32 flash 物理提取）两次行业事件之后，产品升级为"安全芯片存钥 + 可复现构建 + Clear Sign"的 2026 年标准。

**商业模式**：极简——只做签名安全，不提供增值服务，不做托管，不发币。

### 1.2 目标用户

| 用户画像 | 特征 | 核心痛点 | 使用场景 |
|---------|------|---------|---------|
| **长期持有者** | 大额资产冷存储 | 怕丢、怕盗、怕平台跑路 | 私钥离线生成与备份，偶尔签名转出 |
| **DeFi 用户** | 频繁与合约交互 | 盲签钓鱼、恶意授权 | Clear Sign 逐字段确认后签名 |
| **机构/多签成员** | 多人共管金库 | 单点私钥风险 | M-of-N 多签，各自设备独立签名 |
| **数字身份用户** | 通用数字 ID 持有者 | 身份私钥与资产私钥混用风险 | 同一设备隔离派生 ID 密钥与资产密钥 |

### 1.3 产品目标 (OKR)

**O1: 私钥零泄露**
- KR1: 私钥/助记词任何时刻不以任何形式离开安全芯片（含备份环节仅显示一次于屏幕）
- KR2: 通过 EAL6+ 安全芯片认证 + 第三方固件安全审计
- KR3: 签名 nonce 可公开验证（RFC6979 + anti-exfil），无隐蔽通道

**O2: 签名零盲签**
- KR1: 100% 交易在屏幕显示人类可读意图（收款方/金额/授权对象/合约方法）
- KR2: 无法解析的合约调用必须标记"未知风险"并二次确认
- KR3: 用户主动授权前，设备不输出任何签名

**O3: 资产零自毁风险**
- KR1: 设备无任何形式的密钥自毁机制（PIN 超限、拆机均不擦除）
- KR2: PIN 暴力破解在指数退避下等效破解时间 ≥ 10 年（6 位 PIN）

## 3. 核心功能需求

### 3.1 密钥管理（核心）

**用户故事**: 作为持币者，我希望私钥在设备内部生成、永不离开安全芯片，即使连接被黑的电脑也不会泄露。

**功能描述**:
1. **离线生成**
   - 设备开机自检（RNG 健康测试）通过后，在安全芯片内生成种子
   - 熵源：SE 内部 TRNG + 主控 TRNG + 主机可选外部熵，HKDF-SHA256 混合（任一单源失效不致命）
   - 助记词（BIP39，12/18/24 词）仅在屏幕显示一次，手写备份，**不支持任何形式的导出**
2. **密钥派生**
   - BIP32/BIP44 分层确定性派生，多币种路径隔离（m/44'/coin'/account'/change/index）
   - 数字 ID 密钥独立路径（m/44'/id'/...），与资产密钥物理隔离派生
3. **备份与恢复**
   - 恢复时通过屏幕乱序键盘输入助记词（防键盘记录 + 触摸噪声注入）
   - SLIP39（Shamir 分片）作为可选高级备份方案
4. **Passphrase**
   - 可选第 25 词，派生隐藏钱包；支持多 passphrase 多钱包

**验收标准**:
- 助记词显示环节禁止任何通信接口处于数据收发状态
- 恢复流程中，已输入的助记词词在屏幕上以 * 遮蔽
- RNG 启动自检失败时设备拒绝工作并显示错误（不生成任何密钥）

### 3.2 签名（核心价值）

**用户故事**: 作为 DeFi 用户，我希望签名前在设备屏幕上看到"我在给谁、转多少、授权什么"，而不是一段十六进制。

**功能描述**:
1. **Clear Sign 透明签名**
   - 设备端解析交易，屏幕逐字段显示：链、收款地址（首尾缩略+校验和大小写）、金额、手续费、合约方法名（EIP-712 结构化数据按 schema 展示）
   - 无法解析的调用数据显示"未知合约调用"红色警告 + 原始数据哈希，需长按确认
2. **交易签名**
   - BTC/UTXO 系：PSBT 解析与签名（含找零地址归属校验）
   - EVM 系：legacy/EIP-1559 交易 + EIP-712 typed data
   - 签名在安全芯片内完成（RFC6979 确定性 nonce）
3. **消息签名**
   - personal_sign / EIP-712 登录签名，显示完整消息内容
4. **多重签名**
   - M-of-N 配置导入（xpub 集合 + 阈值），设备显示共同签署人列表
   - 每个签名者独立在各自设备上确认同一交易意图
5. **自动签名（限额策略）**
   - 用户预设策略：单笔限额 + 时间窗口限额（如 24h 内累计 ≤ 0.1 ETH）
   - 策略内交易免逐笔确认；超限自动回落到手动 Clear Sign 确认
   - 策略本身只能在设备上修改，修改需 PIN + 24 小时冷静期生效

**验收标准**:
- 屏幕显示地址与签名实际地址不一致 = 严重缺陷，一票否决
- anti-exfil：主机可验证签名熵未被用于夹带私钥
- 自动签名策略状态掉电持久化，重启后严格延续窗口计数

### 3.3 设备安全

**用户故事**: 作为用户，我希望设备丢了别人也取不走我的币，同时我自己绝不会因为设备"自毁"而永久丢币。

**功能描述**:
1. **访问控制（红线：绝对禁止自毁）**
   - PIN 错误指数退避（2^n 秒，封顶 24 小时），**无次数上限，永不擦除**
   - 错误计数与等待截止时间掉电持久化于 SE
   - 胁迫 PIN：打开诱饵钱包视图（小额资产），真钱包不可见、不擦除
2. **固件安全**
   - 安全启动：bootloader 验签固件签名（ECDSA，厂商公钥固化）
   - 升级包签名验证 + 防降级（版本单调递增计数器）
   - 开源固件 + **可复现构建**：用户可自行编译并比对哈希
3. **物理安全**
   - 私钥仅存于 EAL6+ 安全芯片，主控 flash 不存任何密钥材料
   - 防拆检测（tamper mesh）：仅告警提示用户转移资产，**不擦除**
   - 出厂正品验证：SE 内预置一机一密证书，主机端可验真
4. **通信安全**
   - QR 气隙模式优先（摄像头扫入 PSBT/交易，屏幕 QR 输出签名）
   - USB 模式最小数据面：仅传输交易与签名，无调试接口，无固件读写接口

**验收标准**:
- 拆机告警可触发，但密钥材料保持完整可用
- 固件验签失败的升级包一律拒绝，且不影响现有固件
- PIN 退避计时在断电重启后继续（不得清零）

## 4. 非功能需求

### 4.1 安全标准
- SE：CC EAL6+ 认证芯片（候选：航芯 ACL16 / 紫光同芯 / 汇顶 eSE）
- RNG：NIST SP 800-90B 熵源评估 + FIPS 140-3 式启动自检与运行时连续自检
- 签名：RFC6979 + anti-exfil；私钥运算路径常数时间 + 随机掩码
- 供应链：SE Wafer 级根密钥预置，一机一密

### 4.2 可靠性与兼容
- 工作温度 -20℃~60℃；存储 ≥ 10 年数据保持
- 断签恢复：签名中断不产生半签名输出
- 主机端兼容：Sparrow / Electrum / MetaMask（通过 QR 或 bridge）

### 4.3 开源与合规
- 固件、硬件原理图、主机端工具全部开源（OSHW）
- 可复现构建流水线公开发布，版本哈希随 release 公布

## 6. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| 主控被提取 | 高 | 私钥全在 SE，主控零密钥材料 |
| SE 供应锁定/闭源固件 | 中 | 双供应商（航芯/紫光/汇顶）+ 抽象 SE 驱动层 |
| 用户无备份丢设备 | 高 | 首次使用强制助记词手抄确认流程；自毁红线保障永不主动擦除 |
| Clear Sign 解析库滞后于新合约 | 中 | 未知调用一律降级为警告模式，不假装可解析 |
| 自动签名策略被滥用 | 中 | 限额 + 冷静期 + 超限回落手动确认 |
