# HardID 硬件钱包安全核心审核报告

> **日期**: 2026-08-02
> **审核对象**: 《硬件钱包安全核心.md》三条安全原则
> **审核基准**: 2026 年硬件钱包行业最高安全标准（Ledger / Trezor Safe 系列 / Coldcard / Keystone / Blockstream Jade 的工程实践，以及 milk sad、wallet.fail 等公开安全事件的教训）
> **结论**: 方向正确，覆盖不足。三条原则解决了"软件正确性"维度的安全，但缺少物理防御、侧信道、供应链、抗签名侧信道四个维度。按现状不满足最高安全需求。

---

## 1. 三条原则逐项评价

| 原则 | 覆盖到的 | 不足 |
|------|---------|------|
| 1. 完全开源 | 可审计性、抗后门 | 开源 ≠ 可验证。缺**可复现构建**（reproducible builds）——否则用户无法证明下载的固件就是公开源码编译的产物 |
| 2. 最简硬件设计 + 最高随机数要求 | 攻击面小、易审计 | "最简硬件"与"最高安全"存在根本冲突（见 §2-A）；"最高随机数"无具体标准（见 §2-E） |
| 3. 所有操作在钱包完成，屏幕交互，只输出签名结果 | 私钥不出设备、所见即所签的雏形 | 缺防暴力破解、防物理提取、防侧信道；手写触摸屏本身是闭源攻击面（见 §2-G） |

---

## 2. 关键缺口（按威胁严重度排序）

### A. 物理攻击防御 —— 最大空白

- **无安全芯片（SE）**。STM32 主控的内部 flash 已被公开演示可通过电压毛刺提取（2018 年 wallet.fail 对 STM32F2/F4 的成功攻击，BitExchange 正在使用该芯片家族）。2026 年的行业最高标准：**EAL5+/6+ 安全芯片存储私钥**，主控只运行逻辑（Ledger 全系、Trezor Safe 3/5、Coldcard 均为此路线）。
- 无防拆检测（tamper mesh）。注意：物理防拆只做**检测与告警**（标记设备被拆过、提示用户转移资产），不做拆机擦除——理由同 §D，自毁等于替攻击者销毁用户资产。
- 供应链安全缺失：无正品验证（genuine check / 出厂证明 attestation）。

### B. 侧信道攻击 —— 完全未提及

- 功耗分析（DPA/SPA）、电磁泄漏、时序攻击均无对策。
- 最高标准要求：签名路径常数时间 + 随机掩码 + 安全芯片的硬件级抗 DPA。

### C. 签名本身的安全

- **抗 Klepto 攻击（anti-exfil）**：恶意/被篡改固件可在签名 nonce 中夹带私钥逐 bit 外泄。对策：RFC6979 确定性 nonce + 主机可验证的 anti-exfil 协议（Blockstream Jade 已开源实现）。
- **Clear Sign 透明签名**：ETH 盲签是 2023–2025 年盗币主因之一（项目目录已有专项研究文档）。必须从附属研究升级为安全核心条目：签名前屏幕必须显示人类可读的交易意图（收款方、金额、授权对象），实现所见即所签（WYSIWYS）。

### D. 访问控制

**设计红线：绝对禁止自毁机制。** 硬件钱包可能保管着唯一私钥副本，任何形式的自毁（PIN 超限擦除、自毁 PIN、拆机熔断擦除）都会造成资产的永久不可恢复丢失——防盗换来的安全收益远小于用户永久丢币的风险。

- PIN 错误**纯时间成本防御**：指数退避，错误次数越多等待间隔越久（如 2^n 秒封顶数小时/数天），**无次数上限、无自毁**。暴力破解 6 位 PIN（10^6 空间）在指数退避下需要数十年，防护等效。
- 等待状态掉电持久化（写 flash/SE 计数器），防止断电重置计时。
- 胁迫 PIN（duress PIN → 打开只有少量资产的诱饵钱包）保留，**但只切换视图，绝不擦除真钱包**。
- Passphrase（BIP39 第 25 词）支持。

### E. RNG 标准缺失

"最高随机数要求"必须落到可验证的具体标准：
- **NIST SP 800-90B** 熵源健康评估；
- **FIPS 140-3** 式启动自检 + 运行时连续自检；
- **双熵源混合**：安全芯片内部 TRNG + 主控 TRNG + 主机提供熵，经 HKDF 混合，任一单源失效或被操控均不致命；
- 驱动层要求：错误标志恢复、有界轮询、失败安全停机（参照 2026-08-02 对 BitExchange 固件 rng.c 的加固实现，见 `代码/RNG_HARDENING_MEMO.md`）。
- 反面教材：milk sad 事件源于熵实际仅 32 bit——"要求最高"不等于"实现最高"，必须有可测试的标准与自检。

### F. 接口与固件升级

- USB 是攻击面（恶意 HID、固件刷写）。最高标准：**QR 码气隙隔离**（Keystone / Coldcard Q 模式）优先，USB 仅供电或最小数据面。
- 安全启动（secure boot 验签）+ 固件升级签名验证 + 防降级回滚。

### G. 手写触摸输入的隐患

- 触摸控制器固件基本闭源，是可记录输入的恶意硬件候选。PIN/助记词经触摸屏输入必须：**乱序键盘 + 位置随机化 + 输入噪声注入**，且触摸芯片不得具备独立存储与通信能力。
- 手写识别模型**严禁联网**，必须纯本地推理，否则助记词/PIN 有泄露通道。

## 3. 修订建议：HardID 安全核心清单 v2

1. **完全开源 + 可复现构建** + 硬件原理图开放（OSHW）。
2. **安全芯片（EAL6+）存储私钥**，主控最简化运行逻辑；防拆检测（仅告警，不擦除）；供应链正品验证。
3. **RNG**：双熵源混合 + NIST SP 800-90B + 运行时连续自检 + 失败安全停机。
4. 私钥全生命周期不出 SE；签名前屏幕 Clear Sign 确认（WYSIWYS）；RFC6979 + anti-exfil 协议。
5. PIN 指数退避（错误越多等待越久，无上限不自毁，掉电持久化计时）+ 胁迫 PIN（仅诱饵视图）+ passphrase。
6. 抗侧信道：常数时间签名路径 + SE 硬件抗 DPA + 随机掩码。
7. QR 气隙优先，USB 最小数据面；安全启动 + 签名固件升级 + 防降级。

---

## 4. 总评

三条原始原则是正确的安全哲学起点（开放、简单、私钥不出设备），但它们对应的是 2017 年第一代硬件钱包的威胁模型。经 milk sad（熵不足导致真实盗币）与 wallet.fail（STM32 flash 物理提取）两次行业事件后，共识底线已变为：**可复现构建、安全芯片存钥、可验证的 RNG 标准、物理与侧信道防御**。

"最简硬件"理念建议保留在主控与固件设计上（减少攻击面、利于审计），但私钥存储必须交给安全芯片——这不是复杂度妥协，而是物理威胁模型下的必要分层。
