# HardID 硬件选型决策报告

> **日期**: 2026-08-02
> **决策**: **ESP32-P4 + 双 ACL16 安全芯片**
> **状态**: 已定案（用户决策）

---

## 1. 决策结果

| 组件 | 选型 | 角色 |
|------|------|------|
| **主控** | **ESP32-P4**（RISC-V 双核 HP + LP，无射频，MIPI-CSI/DSI） | 交易解析、Clear Sign 渲染、QR 扫码、UI |
| **安全芯片 1 (SE1)** | **航芯 ACL16**（EAL6+） | 「金库」：种子存储、BIP32 派生、ECDSA 签名 |
| **安全芯片 2 (SE2)** | **航芯 ACL16**（EAL6+） | 「守卫」：PIN 验证+退避、SignPolicy、单调计数器、出厂证明 |

---

## 2. 为何 ESP32-P4（而非 STM32 / 其他 ESP32）

### 2.1 三个决定性匹配

1. **RISC-V 开源内核** —— 直接契合安全核心原则 1「完全开源」。从 ISA 到固件全栈可审计，这是 STM32（ARM 闭源）给不了的。
2. **无射频** —— 天生气隙。ESP32-C3/C6/H2 虽同为 RISC-V 开源，但都带 WiFi/蓝牙/802.15.4，与安全核心第 7 条「QR 气隙优先、只输出签名结果」直接冲突。P4 是 ESP32 家族中唯一无射频的高性能型号。
3. **强大算力 + 原生相机** —— Clear Sign 透明签名的核心工作量在**主机不可信数据的本地解析与渲染**：EVM ABI 解码、RLP 解析、大型 PSBT（几十输入）、EIP-712 typed data、QR 解码、大屏渲染。STM32L4 的算力做这些会很吃力（解析延迟 → 用户等待 → 体验崩）。P4 双核 RISC-V + 大 SRAM/PSRAM + MIPI-CSI 原生相机，正是为此而生。

### 2.2 为什么不是 STM32L5

STM32L5（TrustZone、安全启动成熟）是稳妥解，但：
- **ISA 闭源**，违背完全开源原则；
- **算力不足以流畅做 Clear Sign 重解析**（大 PSBT + EVM ABI + 大屏渲染）；
- 无原生 MIPI 相机，V2 气隙扫码需额外 ISP 桥接，增加复杂度。

### 2.3 为什么不是 ESP32-C3/S3

带射频。硬件钱包的射频是头号攻击面，固件"关掉"可被恶意固件重新打开——否决。

## 3. 为何双 ACL16（而非单 SE）

不是堆料，是**职责分离 + 熵源独立**：

### 3.1 职责分离（映射 se_driver 接口的天然拆分）

现有 `se_driver_t` 接口恰好分为两组，双 SE 各管一组，**单点被攻破不全局失守**：

| SE1「金库」 | SE2「守卫」 |
|-------------|-------------|
| `store_seed` / `is_initialized` | `verify_pin`（含退避状态） |
| `sign_digest` / `get_xpub` | `policy_authorize`（限额计数） |
| `get_random`（TRNG#1） | `monotonic_read/increment`（防降级） |
| | `attest`（出厂证明） |
| | `get_random`（TRNG#2） |

- SE1 只碰密钥；SE2 只碰访问控制与状态。**即使 SE1 被物理攻破，PIN 退避与策略计数仍在 SE2 保护下**，攻击者无法绕过时间成本；即使 SE2 被攻破，私钥仍在 SE1。

### 3.2 三源熵升级（摆脱主控 TRNG）

`seed.c` 的 HKDF 三源混合原设计是 `SE_TRNG + MCU_TRNG + host_entropy`。双 ACL16 后：

```
IKM = SE1_TRNG(32) || SE2_TRNG(32) || host_entropy
PRK = HMAC(salt="HardID seed v1", IKM)
seed = HMAC(PRK, "mnemonic" || 0x01)
```

**两个独立 EAL6+ 熵源 + 主机熵**，主控 TRNG 完全退出信任链——即使 ESP32-P4 的 TRNG 有缺陷或被影响，种子强度不受影响。这比单 SE + 主控熵的方案更纯粹。

> **2026-08-11 软件侧补充（正交，不影响本硬件定案）**：在生产双 ACL16 未就绪前，
> S3 测试板已实现 Layer A 物理熵池（`core/phys_entropy.c` + entropy_s3.c/p4.c）——
> 触摸/温度传感器/总线时序/RTC 四源经无条件 SHA-256 池混入 HKDF（设计见
> 08_多熵源设计.md）。此纯固件层在硬件按 3.2 就位后仍叠加使用，进一步加厚
> "SE TRNG 被旁路/后门"场景下的纵深防御。

### 3.3 签名授权双重确认（可选增强）

双 SE 可扩展为：**SE1 签名前要求 SE2 的解锁令牌**（SE2 在 PIN 验证通过后签发短时令牌）。这样"签名需 PIN 授权"的不变量由**两颗独立芯片交叉强制**，而非单 SE 自证——第 16 轮审计发现的"解锁不变量"获得硬件级纵深。

## 4. 对软件架构的影响（se_driver 已就绪）

现有 `se_driver_t` 抽象**无需重构**，只需一个组合驱动路由到两颗 SE：

```c
/* se_composite.c — routes se_driver calls to SE1 (vault) or SE2 (guard) */
static const se_driver_t composite = {
    .get_random      = se1_get_random,      /* or XOR of both */
    .store_seed      = se1_store_seed,
    .is_initialized  = se1_is_initialized,
    .sign_digest     = se1_sign_digest,
    .get_xpub        = se1_get_xpub,
    .verify_pin      = se2_verify_pin,
    .policy_authorize= se2_policy_authorize,
    .monotonic_read  = se2_monotonic_read,
    .monotonic_increment = se2_monotonic_increment,
    .attest          = se2_attest,
};
```

`seed.c` 的 `os_seed_se_trng` hook 需扩展为**读两颗 SE 并各自喂入 HKDF**（当前是单 buffer，改为两段 update）。

## 5. 关键规格确认（下一步必须验证）

| 项 | 风险 | 动作 |
|----|------|------|
| **ACL16 是否硬件原生支持 secp256k1** | **高** —— 若否，ECC 退回软件，侧信道暴露面大增，SE 方案需重评 | 查 ACL16 数据手册/联系航芯 FAE |
| ESP32-P4 量产与供货/价格 | 中 | 确认渠道、交期、单价 |
| ACL16 供货与 NDA/ datasheet 获取 | 中 | 签 NDA 拿完整手册 + SDK |
| 双 ACL16 通信拓扑 | 低 | 共享 SPI（不同 CS）还是独立 SPI/I2C？P4 SPI 资源丰富，建议独立总线隔离 |

---

## 6. 成本与复杂度权衡（诚实记录）

- **双 ACL16 成本翻倍**：BOM 增加一颗 EAL6+ 芯片。对安全产品合理，但需在定价中体现。
- **P4 复杂度高于 STM32**：电源树、PSRAM、MIPI 布局更复杂，PCB 层数可能增加。
- **供应链新**：P4 较新，需验证长期供货承诺（ESP32 通常有 10 年 longevity 计划，需确认 P4 在内）。

---

## 7. 结论

**ESP32-P4 + 双 ACL16** 是三个维度的最优交集：
- **开源原则**：RISC-V 开源内核 + 完全开源固件 + 可复现构建
- **气隙安全**：无射频 + QR 相机 + 双 EAL6+ 独立存钥与守卫
- **Clear Sign 体验**：双核算力支撑本地重解析与大屏渲染，透明签名不牺牲流畅性
